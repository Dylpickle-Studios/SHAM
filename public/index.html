Guide

Documentation

Task-oriented guides for the dashboard, deployments, runtimes, CI/CD, the API, configuration, operations, security, plugins, and troubleshooting.

Deploying a project

Create a site, choose a ZIP/folder or Git repository, then select a runtime driver. Static mode serves assets directly; managed-process presets cover Node/npm, Bun, Deno, FastAPI, Django, Go, Java, and custom commands; container mode supports images, Dockerfiles, Cloud Native Buildpacks, and Nixpacks; Compose and reverse-proxy modes cover multi-service and externally managed applications. SHAM injects HOST and the configured port environment variable.

Upload formats and troubleshooting

Use a standard, non-encrypted ZIP or the folder chooser. SHAM removes one common enclosing folder before checking the entry path, so website/index.html uses the entry index.html. A ZIP must really be ZIP data, not a renamed 7z, tar, or split archive. Folder uploads preserve browser-relative paths and are limited to 2,000 files.

When an upload reports that its temporary file is unavailable, verify that SHAM_DATA_PATH is writable and that no host cleanup task removes its tmp directory. In Docker, verify the persistent volume's ownership. For rejected or interrupted uploads, also check SHAM_UPLOAD_LIMIT_MB, SHAM_REQUEST_TIMEOUT_SECONDS, and reverse-proxy body and timeout limits.

Runtime presets and manifests

Legacy Node.js sites remain compatible with a configured entry file and optional production dependency install. New managed-process sites can use a preset or a custom start command. Repositories may include a reviewed sham.yaml, sham.yml, or sham.json; execution-policy changes require explicit approval before Git activation. Readiness probes gate traffic switching, while health probes supervise the active release.

const express = require('express');
const app = express();
app.get('/', (_req, res) => res.send('Hello from SHAM'));
app.listen(process.env.PORT, process.env.HOST || '127.0.0.1');

Files and editor

Open Files on a site to browse text documents, create or edit a file, replace one file, or delete one file. The browser renders at most 500 matching paths at once; refine the filter for very large projects. Static changes are visible immediately. Restart a Node.js site after server-side code changes.

Minification and obfuscation

Minification compresses HTML, CSS, and JavaScript while serving static projects. Obfuscation uses a compatibility-oriented mode that avoids top-level/property mangling and preserves function and class names. SHAM falls back to the original asset when transformation fails, but runtime reflection and dynamically generated code cannot be proven safe. Enabling it requires an explicit acknowledgement; existing sites can run a compatibility report first. Source files remain unchanged, and obfuscation is not a security boundary.

Domain-only access and firewall

Domain-only access rejects requests whose Host header does not match the configured domain. The local firewall can allow or block IP/CIDR ranges and countries, limit requests per IP, cap request bodies, and block obvious automated clients. Cloudflare or Both mode can synchronize the IP and country policy to a hostname-scoped Cloudflare WAF custom rule. Cloudflare identity headers are trusted only from Cloudflare or reverse-proxy peers explicitly configured by the operator.

Traffic intelligence and performance

The overview records bounded visitor activity and country totals. Country values come from trusted Cloudflare geolocation headers; direct visits appear as Unknown. The Performance page samples SHAM CPU, memory, event-loop delay, disk use, worker queues, hosted request rate, throughput, errors, runtime memory, health checks, connections, and restart activity. Use Performance for per-site alert rules and Settings → Instance for instance-level observability/retention controls.

Snapshots and dependency safety

Open a site's Safety tools to create restore points, roll back a deployment, or scan Node.js dependencies. SHAM creates an automatic rollback snapshot before risky replacements and restores. Dependency scans combine lockfile-aware npm audit data when the registry is available with local checks for risky scripts, missing lockfiles, and exposed secrets. Keep independent backups of the complete data directory.

Runtime resilience

Managed runtimes support startup/readiness and liveness probes, readiness-first blue/green release switching, graceful drain/shutdown windows, restart policies, exponential backoff, crash-loop protection, resource limits, connection limits, request timeouts, and bounded health-check concurrency. Process and container exits are reconciled after control-plane restarts. Static sites can serve precompressed .br or .gz assets and negotiate on-the-fly Brotli/Gzip.

Safe delivery and previews

The administrator-only Operations workspace can deploy a Git branch into a new release, validate and start it, switch traffic atomically, and retain the previous release for rollback. Signed HMAC webhooks can trigger the same serialized workflow. Preview hostnames are temporary validation environments and expire automatically.

Isolation and Anubis

Container runtimes use a constrained Docker boundary with a separate writable data mount, resource limits, dropped capabilities, no-new-privileges, and optional outbound-network blocking. Dockerfile/Buildpack/Nixpacks candidates are built before promotion, and legacy Docker-isolated Node dependencies are installed inside the runtime-compatible image. Compose rejects privileged/host-namespace/device/capability/Docker-socket/host-bind configurations and unmanaged auxiliary host ports. Docker access still grants SHAM substantial host control, so use a dedicated host or VM. Anubis remains an optional per-site anti-bot sidecar.

Secrets, jobs, and attached services

Per-site environment values and reusable database connection profiles are encrypted at rest; secret values are masked by default and an administrator must confirm the current password to reveal one. Scheduled jobs use bounded five-field cron expressions, prevent overlapping runs, enforce a timeout, and capture output. Restart or redeploy a site after changing runtime configuration.

Backups and updates

Operations supports local, restic, S3-compatible, and SFTP backups. Restic provides repository encryption; other destinations rely on their storage encryption unless wrapped by restic. Safe SHAM updates are extracted and signature-checked off the main thread, require explicit acknowledgement when unsigned, create a managed-file backup, and roll back after failed startup. Dependency-changing updates must be installed through a normal reviewed release.

Dependency security

The container build fails when npm audit reports a high- or critical-severity production dependency. ZIP parsing uses adm-zip 0.6.0, Multer is pinned to 2.2.0, and nested multipart field parsing is disabled on every upload endpoint. Authentication uses jsonwebtoken 9.0.3 so its JWS dependency resolves to the patched 4.0.1 line. Keep a reviewed lockfile in published builds and rerun the audit whenever dependencies change.

Operational routing and observability

Sites can define maintenance pages, redirects, custom error responses, cache rules, security headers, and WebSocket-aware edge routing. Runtime logs support search and saved filters; audit logs are exportable. Optional Prometheus, OpenTelemetry, alert destinations, public status, and English, Dutch, or German interface settings are available under Operations.

Public endpoints and outbound data

The unauthenticated health endpoint returns only a boolean readiness result. Public status is opt-in and publishes service names with coarse health states, never domains, ports, logs, or configuration. Prometheus requires a bearer token and fails closed when no token is saved. Signed deployment webhooks use uniform authentication errors and do not return internal deployment details. Alert, backup, Cloudflare, and OpenTelemetry destinations are administrator-configured trust boundaries; HTTP redirects are rejected before credentials or telemetry are sent.

Database and local storage

SHAM uses parameterized better-sqlite3 statements directly rather than an ORM. SQLite runs with WAL, foreign keys, a busy timeout, bounded retention, and indexes for visitor lookups. Database, upload, snapshot, update, backup, key, and temporary credential files are owner-only on POSIX systems. Backup archives contain the database and encrypted secrets, so protect remote destinations and the encryption keyring together.

Account and secret security

Enable TOTP and passkeys under Security, then store recovery codes offline. Saved integration, plugin, and TOTP secrets are encrypted with an instance master key. Administrators can rotate that key after taking a storage backup. Runtime and audit logs are structured and retention-limited; visitor privacy can store full, masked, or pseudonymous addresses.

Security headers and shared edge ports

Per-site security presets add CSP and related browser protections. The optional shared edge proxy accepts hostnames on ports 80 and 443 and routes them to private site listeners, allowing many sites to share standard ports and certificates. Keep the dashboard and origin listeners firewalled from untrusted networks. Certbot temporarily coordinates with the shared port-80 listener when standalone validation is required.

Appearance

Open Settings → Appearance to choose System, Light, or Dark color mode independently from the Purple, Midnight, Emerald, or Custom palette. Semantic theme tokens apply to built-in pages, dialogs, status surfaces, tables, charts, and plugins that reuse SHAM components. Appearance preferences are saved only in this browser.

SSL and Cloudflare

Set a domain, configure a Certbot email under Instance, then choose Issue SSL. With a Cloudflare API token configured, SHAM uses the DNS challenge; otherwise standalone validation requires public port 80. Cloudflare DNS synchronization creates or updates a proxied A record, while optional WAF synchronization mirrors supported site firewall rules. A proxied record does not protect an origin that remains directly reachable, so allow only the shared edge listener or Cloudflare source ranges as appropriate.

Docker storage

Set SHAM_DATA_PATH to any writable directory. In Docker, mount persistent storage there, such as /data. Back up the database, master keyring, sites, plugins, snapshots, and Certbot data together.

With the supplied Compose file, dashboard changes and hosted content persist in the host-mounted ./sham-data directory. Compatible UI-staged SHAM code updates are stored under /data/app-runtime in SHAM 1.0.0 and survive container recreation. Any update that changes runtime dependencies must be installed through a reviewed image rebuild.

Runtime model

SHAM separates application technology from orchestration. The built-in drivers are static, process, container, Docker Compose, and reverse proxy. Language/framework choices are presets over those drivers, so Node, Bun, Deno, Python, Go, Java, and custom binaries share the same readiness, health, logging, restart, and release lifecycle.

Existing Docker images

Choose Docker image as the source when the application already exists in an OCI-compatible image. Enter the registry-qualified image name and the container port the application listens on. SHAM uses Docker's normal registry configuration, so authenticate private registries on the Docker host before deploying. Existing-image mode does not mount the site source directory over the image filesystem; the image keeps its own WORKDIR and files.

ghcr.io/acme/api:2026-08-13
registry.example.com/team/service:v4

Dockerfile builds

Use an uploaded project or Git repository and choose the Dockerfile container source. The Dockerfile path must stay inside the deployment tree. SHAM builds a candidate image, starts it with constrained runtime flags, waits for readiness, and only then switches traffic. A failed candidate is cleaned up without replacing the active release.

Docker Compose

Compose is intended for an application service plus private supporting services such as a database, queue, or cache. Choose the Compose file and the application service. On a host installation, SHAM can publish the selected application service to a random loopback port when the Compose file has no published port. Auxiliary services must not publish host ports.

For safety, SHAM rejects privileged containers, host networking/PID/IPC, added Linux capabilities, devices, Docker-socket mounts, host bind mounts, external namespace escape settings, unmanaged auxiliary host ports, and other configurations that bypass the managed boundary. Use named volumes for application data. If outbound networking is disabled, SHAM applies internal Docker networks to the managed project.

Buildpacks and Nixpacks

These modes convert source code into an OCI image and then use the same container runtime. They require the corresponding pack or nixpacks executable on the SHAM host. Missing tooling fails before traffic is changed.

Process runtimes

Custom processes receive HOST=127.0.0.1 and a reserved internal port through the configured port environment variable. Prefer structured argv in sham.yaml when arguments may contain whitespace. Configure HTTP readiness for applications that need initialization after opening a socket.

Probes and shutdown

Readiness determines when a candidate may receive traffic; liveness supervises the active backend. TCP, HTTP, and command probes are available. Shutdown sends a graceful termination signal, waits for the configured grace period, then force-stops the backend if required. Blue/green drain time lets existing requests leave the previous backend after the traffic switch.

Git providers

SHAM supports GitHub, GitLab, Bitbucket Cloud, Gitea, Forgejo, and manually entered Git URLs. Gitea and Forgejo can use a self-hosted base URL. Provider access tokens are encrypted and injected into Git without placing their value in clone command arguments.

Repository discovery

Connect a provider under Settings → Instance → Git provider connections, then choose it in the new-site wizard to browse repositories. A pasted HTTPS or SSH repository URL remains available when a provider is not connected.

Push webhooks

Set the public SHAM URL in Git provider settings. After a Git deployment, SHAM can create or reconcile a push webhook using the provider API. Deployment webhooks use a per-site encrypted secret and provider-specific signature/token verification. Treat the public webhook endpoint as internet-facing even though invalid signatures receive only a generic authentication error.

Release flow

  1. Clone the requested commit/branch into an isolated staging release.
  2. Apply approved sham.yaml policy and run install/build steps.
  3. Move the release to its immutable final path.
  4. Start a candidate backend and wait for readiness.
  5. Switch the gateway to the candidate and drain the previous backend.
  6. Persist the active release and retain prior releases for rollback.

If candidate startup, readiness, promotion, or activation bookkeeping fails, SHAM restores the previous backend or tears down the first candidate instead of leaving traffic and database state split.

Errors and limits

JSON API errors use an HTTP status plus an error message. Upload endpoints use multipart form data and enforce file-count, field-count, size, and timeout limits. Clients should handle 401, 403, 409, 413, and 429 without blindly retrying unsafe requests.

Configuration map

SHAM loads .env from the project root and gives existing process environment variables precedence. Keep SHAM_DATA_PATH persistent/private and supply SHAM_JWT_SECRET from a secret store in production.

Runtime executables

Optional capabilities use configurable executable paths: SHAM_DOCKER_BIN, SHAM_PACK_BIN, SHAM_NIXPACKS_BIN, SHAM_GIT_BIN, SHAM_CERTBOT_BIN, SHAM_CLOUDFLARED_BIN, SHAM_RESTIC_BIN, SHAM_AWS_BIN, and SHAM_SFTP_BIN. Missing optional tools should affect only the related capability.

Docker-in-Docker control path

When SHAM itself runs in Docker while controlling the host daemon, set SHAM_DOCKER_HOST_DATA_PATH to the absolute host path corresponding to the mounted SHAM_DATA_PATH. The internal/egress network names control managed Docker routing/isolation.

Concurrency and limits

Upload, npm install, minification, compression, dependency scan, snapshot, health-check, performance-sampling, job, Git, backup, and plugin operations have explicit timeout/worker/queue bounds. Increase them only after considering memory/CPU/disk pressure.

Settings map

Secrets and environment values

Environment variables can be scoped to build, runtime, or both. Secret values are encrypted and masked in the browser. Revealing a stored secret requires administrator re-authentication. Container secrets are not deliberately placed in Docker CLI KEY=value arguments.

Backups and recovery

Backups may target local protected storage, Restic, S3-compatible storage, or SFTP. Restore first validates every archive entry, rejects links/special files and unsafe paths, extracts into an isolated staging directory, verifies the SQLite database with PRAGMA quick_check, then atomically swaps the data directory. A failed swap restores the previous directory.

Performance and alerting

The Performance page reports SHAM CPU/memory/event-loop/disk/queue health and per-site CPU, requests, errors, latency, memory, health, connections, and restarts. Per-site history stores p50/p95 latency and CPU samples. Administrators can define site-specific thresholds in addition to instance-wide alert settings.

Cloudflare Tunnels

Sites can use dedicated cloudflared connectors or one instance shared connector. Save a Tunnel token under Sites → Site settings → Cloudflare Tunnel, then verify both Connected and the separate loopback-origin health check under Settings → Instance. Tunnel tokens are separate from the DNS/WAF/Certbot token and from the optional least-privilege Tunnel management API token.

With the standard Docker Compose edge listener, a Tunnel public-hostname service normally points to http://localhost:80 from inside the SHAM container; SHAM then routes by hostname. The optional management API can provision and reconcile remote hostname routes. Tunnel-only mode requires a loopback site listener, but operators must still keep Docker and shared-edge host mappings private.

Cloudflare DNS/WAF and TLS

Cloudflare DNS/WAF reconciliation is optional and separate from Tunnel routing. Certbot can use Cloudflare DNS credentials or standalone validation. Keep origin listeners private where possible and do not assume a proxied DNS record makes an otherwise exposed origin unreachable.

OIDC and local accounts

OIDC uses Authorization Code + PKCE, state and nonce validation, JWKS signature verification, issuer/audience/time checks, and optional first-login provisioning. SSO-provisioned users can set a local password from Security for password-confirmed actions, then use TOTP, recovery codes, WebAuthn, and local sign-in normally.

API tokens

API tokens are personal credentials intended for CLI and CI/CD automation. Use narrow scopes, rotate/revoke on suspected exposure, and prefer a dedicated automation account where operational separation matters.

Release hygiene

Run the project test suite and npm run release:check before distributing source. The release check rejects generated JWT secrets, environment files, live databases/WAL files, master-key material, and other runtime data from the source tree.

Plugin packages

A plugin is a ZIP containing plugin.json at its root. JSON plugins are declarative UI and data extensions. JavaScript plugins can register server actions, query SHAM data, store settings, and load a browser client.

Declarative SQL is intentionally restricted: it cannot access users, instance secrets, plugin settings, audit logs, or SQLite schema tables, and write actions cannot directly mutate site or plugin lifecycle rows.

Declarative actions

JSON plugins may declare named get, all, or run SQL actions. Read actions accept one comment-free SELECT statement. Write actions accept one INSERT, UPDATE, or DELETE statement, require an administrator, and require a non-GET request. Cards bind to an action with action and select a result using valuePath. Use placeholders rather than building SQL strings.

Settings

Declare settings in plugin.json. SHAM renders a dedicated themed settings page and passes values to server plugins through settings.get(), settings.all(), and settings.set(). Password values are never sent back to the browser; leave them blank to preserve them or use the clear control.

UI theme and lifecycle

Render only inside the supplied plugin container and reuse SHAM classes such as panel, stat-card, table-wrap, button, muted, and notice. Do not replace the dashboard shell. Add a client deactivate() hook when you attach timers, observers, or global listeners. SHAM awaits cleanup with a bounded timeout during reload, disable, deletion, and shutdown. Server activate() must return synchronously; action handlers may be asynchronous.

Permissions and runtime API

Request only the permissions the plugin needs: data:read, data:write, settings:read, settings:write, ui:dashboard, network:outbound, runtime:read, or runtime:manage. With runtime permission, plugins can inspect sites or invoke runtime.start(), runtime.stop(), and runtime.restart(). Worker-isolated calls are asynchronous and bounded, so await data and runtime operations.

Signatures and isolation

Packages may carry an Ed25519 signature referencing a trusted publisher key configured by an administrator. Unsigned packages require an explicit install acknowledgement unless instance policy permits them. Set "isolation": "worker" to restrict module imports, code generation, host RPC, and action concurrency. Worker isolation reduces accidental interference but is not an OS sandbox; reviewed JavaScript can still access the data and capabilities granted by its permissions.

UI and performance discipline

Reuse semantic SHAM components so custom pages inherit every theme. Avoid global DOM mutations, unbounded timers, large synchronous loops, or repeated polling. Clean up timers, observers, and listeners in deactivate(). Action handlers have bounded time and concurrency; return compact JSON and paginate large data sets.

Common problems

Folder upload says “Too many fields”

The current site form uses a bounded multipart field allowance with headroom for the expanded runtime configuration. On an upgraded build, check any reverse proxy/WAF multipart limits before changing SHAM's server limits.

Docker/Compose fails

Verify Docker access, container port, readiness path, and SHAM_DOCKER_HOST_DATA_PATH when SHAM is containerized. Compose intentionally rejects privileged/host namespace, host bind, Docker socket, unmanaged external resources, support-service host ports, and related escape-prone configuration.

Git repository/webhook fails

Verify provider token/base URL, repository ownership/matching, webhook HTTPS reachability, signature/token, branch, delivery ID, and deployment logs. Gitea/Forgejo require the correct self-hosted base URL.

Manifest approval required

A repository manifest changed execution policy. Review it like executable infrastructure code and approve only when the commit is trusted.

CI reports a generated JWT secret

Run npm run release:check and ensure tests supply a test JWT secret instead of causing configuration startup to generate data/.jwt-secret in the source tree.

Popup appears behind a modal

Hard-refresh after upgrading, then check plugin/custom CSS if the current top-layer tooltip/toast behavior is still being overridden.
